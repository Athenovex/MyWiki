# 문서 작성규칙

## Canonical Note (`10_위키`)

단순 원문 요약이 아니라 여러 출처의 지식을 통합한 대표 설명 문서다.

기본 골격:

```markdown
# 문서명

> 핵심 정의 (한두 문장)

## 개요

## 핵심 내용

## 관련 지식

## 출처
```

내용 성격에 따라 섹션을 추가할 수 있다.

**도구/제품 문서 예시**: 개요 / 주요 기능 / 작동 방식 / 활용 / 장점 / 제약 / 관련 지식 / 출처
**개념 문서 예시**: 개요 / 핵심 원리 / 작동 방식 / 활용 / 관련 개념 / 출처

빈 섹션을 억지로 채우지 않는다. 내용이 없으면 섹션 자체를 생략한다.

### 시간에 따라 바뀌는 지식

가격·제품 기능·정책·법규 등 변경 가능한 내용은 영구적인 정의와 구분한다.

```markdown
## 현재 기능

## 변경 이력
```

오래된 출처로 최신 정보를 덮어쓰지 않는다.

## Source Note (`20_출처`)

메타데이터 + 분석 + 위키 반영 기록 역할. 제2의 원문이 되지 않도록 지나치게 길게 쓰지 않는다 (원본은 이미 `_원본`에 보존됨).

```markdown
# 자료명

## 원본

## 자료 개요

## 핵심 내용

## 위키 반영

## 참고
```

### 근거 위치 표기

가능하면 세부 근거 위치를 남긴다.

| 자료 유형 | 표기 예시 |
|---|---|
| PDF | `[[AI Agent Report]] p.42–45` |
| PPT | `[[AI Automation Seminar]] slide 18` |
| Video/Audio | `00:03:15 AI Agent 정의` |
| Spreadsheet | Sheet명 또는 데이터 범위 (의미 있을 때만) |

## 신뢰성 표기

자료가 존재한다고 모두 사실로 반영하지 않는다. 공식 자료 / 연구 / 보도 / 블로그 / 의견 / 홍보 자료 / SNS / 미확인 주장을 구분한다. 상충하는 출처는 단일 사실처럼 합쳐 쓰지 않고, 필요하면 Source Note에 신뢰성 메모를 남긴다.
