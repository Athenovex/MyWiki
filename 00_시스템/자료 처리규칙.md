# 자료 처리규칙

## 처리 Workflow

`01_수집`의 모든 신규 자료는 다음 9단계를 거친다.

```
INTAKE → EXTRACT → UNDERSTAND → SEARCH → RECONCILE → UPDATE → CITE → ARCHIVE → AUDIT
```

1. **INTAKE** — 파일 종류·출처·날짜·작성자·분석 가능 여부·중복 원본 여부 판단
2. **EXTRACT** — 자료 유형에 맞는 방식으로 내용 추출 (원본 훼손 금지)
3. **UNDERSTAND** — 주제·핵심 주장·새로운 사실·개념·도구·방법 파악
4. **SEARCH** — `10_위키` 전체(파일명·aliases·id·본문)를 반드시 먼저 검색
5. **RECONCILE** — [[병합 규칙]]의 SAME/BROADER/NARROWER/RELATED/NEW로 판정
6. **UPDATE** — 병합 규칙의 업데이트 절차대로 반영
7. **CITE** — Source Note와 연결, 가능하면 세부 근거 위치 포함
8. **ARCHIVE** — 원본은 `20_출처/_원본`, Source Note는 `20_출처`로 이동
9. **AUDIT** — [[위키 점검 규칙]]대로 무결성 확인

## 파일 처리 공통 원칙

파일을 발견하면 먼저: ① 파일 형식 ② 파일 크기 ③ 정상적으로 읽히는지 ④ 이용 가능한 도구 ⑤ 분석 방법 ⑥ 원본 변형 필요 여부를 확인한다. **원본 파일 자체는 절대 수정하지 않는다.** 필요하면 임시 파일로 처리한다.

## 지원되지 않는 파일

신뢰성 있게 읽을 방법이 없으면 **추측하지 않는다.** 순서대로 시도: ① 사용 가능한 로컬 도구 확인 → ② 안전한 변환 방법 사용 → ③ 변환 결과 기반 분석 → ④ 그래도 불가능하면 `80_검토`로 이동하며 Source Note에 다음을 기록:

```
분석 상태: 자동 분석 불가
이유: ...
필요 작업: ...
```

## 형식별 처리 방법

### PDF
텍스트 추출 → 구조/목차 확인 → 표·도표·이미지 존재 확인 → 필요시 페이지 단위 분석 → 핵심 개념 추출 → 기존 위키 비교. 텍스트 레이어가 있으면 OCR 불필요. 스캔본처럼 텍스트가 없을 때만 OCR을 검토한다. 근거에 페이지 번호 보존.

### 이미지 (PNG/JPG/WEBP 등)
먼저 성격 판단: **사진**(시각 내용 분석) / **다이어그램**(구조·관계 분석) / **UI 스크린샷**(화면 구조+텍스트+기능 분석) / **스캔 문서**(문자가 핵심이면 OCR 검토, 무조건 실행하지 않음).

### Word/일반 문서 (DOCX 등)
제목·Heading 구조·본문·표·목록·메타데이터를 보존하며 추출. 시각적 서식보다 내용 구조를 우선.

### 프레젠테이션 (PPTX 등)
슬라이드 제목·본문·핵심 도표·슬라이드 간 흐름·주요 주장 분석. 근거에 슬라이드 번호 남김.

### 스프레드시트 (XLSX/CSV 등)
전체를 무조건 문장으로 변환하지 않는다. 먼저 Sheet 구조·Column 의미·데이터 규모·핵심 지표·반복 패턴·위키 반영 가치를 판단. 단순 원시 데이터면 Source로만 보존하고 불필요한 Wiki Note를 만들지 않는다.

### 영상 (MP4/MOV 등)
`메타데이터 확인 → 오디오 추출 가능 여부 → Transcript 생성 → 필요시 주요 장면 분석 → 핵심 개념 추출 → 기존 Wiki 검색`. 영상 전체를 신뢰성 있게 분석할 수 있다고 가정하지 않는다.

### 음성 (MP3/WAV/M4A 등)
`Transcript → 내용 분석 → 기존 Wiki 비교 → 지식 반영`. 근거에 타임코드 남김.

### Transcript 생성
도구가 없으면 임의로 만들지 않는다. 기존 자막 존재 여부 확인 → 로컬 transcription 도구 확인 → 둘 다 없으면 `80_검토`. 생성되면 가능한 한 타임코드 유지.

## OCR 정책

기본 처리 방식이 아니다. 스캔 PDF, 촬영 문서, 이미지 속 문자가 핵심 정보, 일반 텍스트 추출 불가 — 이 경우에만 고려한다. OCR 결과는 오류 가능성이 있으므로 중요한 사실은 원본과 대조한다.

## 중복 원본 처리

동일 파일이 여러 번 들어와도 파일명만으로 판단하지 않는다. 가능하면 파일 크기·내용·제목을 비교한다. 완전 동일한 원본이면 중복 Source를 만들지 않는다. 판단이 불확실하면 삭제하지 않고 `80_검토`로 보낸다.

## `_첨부`와 `20_출처/_원본`의 차이

- `_첨부`: Wiki Note 안에서 직접 보여주기 위한 이미지·캡처·다이어그램·썸네일
- `20_출처/_원본`: 지식의 근거가 되는 실제 원본 파일 (PDF·영상·사진·문서·PPT·오디오·데이터)

두 역할을 섞지 않는다.

## 현재 환경에서 실제 사용 가능한 도구

이 목록은 환경이 바뀌면 함께 갱신한다. 최신 확인은 `pandoc --version`, `ffmpeg -version` 등으로.

| 형식 | 처리 방식 | 상태 |
|---|---|---|
| Web | Web Clipper로 수집 | 사용 가능 |
| PDF | Read 도구로 직접 텍스트/페이지 추출 | 사용 가능 (스캔본은 OCR 도구 필요 → 현재 없음) |
| Image | 시각적으로 직접 분석 | 사용 가능 |
| DOCX | 문서 처리 Skill 사용 | 사용 가능 |
| PPTX | 프레젠테이션 처리 Skill 사용 | 사용 가능 |
| XLSX/CSV | 스프레드시트 Skill 또는 직접 읽기 | 사용 가능 |
| TXT | 직접 읽기 | 사용 가능 |
| EPUB | 별도 변환 도구 필요 | 현재 자동 처리 어려움 → `80_검토` |
| Video | ffmpeg/transcription 도구 필요 | 현재 미설치 → `80_검토` |
| Audio | transcription 도구 필요 | 현재 미설치 → `80_검토` |
