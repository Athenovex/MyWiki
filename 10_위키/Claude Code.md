# Claude Code

> 터미널 또는 [[Claude]] 데스크톱 앱의 **Code 탭**에서 동작하는 코딩 에이전트. 파일을 읽고, 코드를 수정하고, 명령을 실행하는 등 실제 작업을 대신 수행한다. 예전엔 터미널 명령어가 필요했지만 데스크톱 앱의 Code 탭으로 코딩 지식 없이도 쓸 수 있게 됐다.

## 개요

Claude Code는 "저장소 전체를 읽고 버그 수정·리팩토링·문서화·테스트 작성까지 맡기는" 기본 엔진이다. 앱 상단의 Chat(질문용) / Cowork(백그라운드 작업용) / Code(실제 작업용) 3개 탭 중 Code 탭이 진짜 작업이 이뤄지는 곳이며, **Local**을 선택해 작업 폴더를 지정하면 그 폴더 안에서만 파일 읽기·쓰기가 허용된다. 기본은 **Manual 모드**로, 파일을 바꾸기 전 미리 보여주고 **Accept(수락)**를 눌러야 적용된다.

## `.claude` 폴더 구조

`.claude` 폴더는 "클로드에게 주는 신입사원 매뉴얼"에 비유된다. 안에 담기는 요소는 크게 세 종류다.

### 1) 설명서 — 프로젝트가 뭔지 알려주는 문서

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 프로젝트 정보·작업 규칙을 담은 핵심 매뉴얼. `.claude` 폴더에서 가장 중요한 파일 |
| `CLAUDE.local.md` | 팀에는 안 보이는 개인 전용 메모 버전 |
| `.gitignore` | 팀과 공유하지 말아야 할 파일 목록 (개발 표준, Claude 전용은 아님) |
| `.mcp.json` | Notion·GitHub·DB 등 외부 앱과의 연결 설정 |
| `.worktreeinclude` | 여러 작업방(worktree)을 열 때 함께 챙길 파일 목록 (고급) |

### 2) 규칙·권한 — 뭘 해도 되는지 정하는 것

| 파일 | 역할 |
|---|---|
| `settings.json` | 위험한 작업은 막고 안전한 작업은 매번 묻지 않고 통과시키는 권한 규칙. `CLAUDE.md`가 "부탁"이라면 이건 "강제 규칙" |
| `settings.local.json` | 팀 설정은 그대로 두고 개인 환경만 조정하는 버전 |

### 3) 도구·기능 — 자주 쓰는 작업을 저장해두는 도구상자

| 폴더 | 역할 |
|---|---|
| `rules/` | `CLAUDE.md`가 길어질 때 주제별(테스트, API 설계 등)로 나눠 특정 작업 시에만 켜지는 규칙 |
| `skills/` | 작업 레시피 모음. 폴더 하나 = 스킬 하나(`SKILL.md` + 참고 파일). [[Claude 에이전트 스킬]] 참고 |
| `commands/` | 긴 지시를 `/이름` 단축 명령어로 저장 (파일명이 곧 명령어가 됨) |
| `agents/` | 코드 검토 전담 등 특정 업무만 맡는 보조 에이전트. 자기 공간에서 따로 일하고 결과만 보고 |
| `hooks/` | "저장 시", "명령 실행 직전" 등 특정 타이밍에 자동 실행되는 스크립트. `settings.json`에 등록해야 작동함 |
| `output-styles/` | 답변 말투·형식(가르치듯, 간결하게 등)을 상황별로 전환 |
| `workflows/` | 여러 단계를 하나의 `/이름` 명령으로 묶어 순차 재실행 |
| `agent-memory/` | 서브에이전트가 스스로 배운 패턴·주의점을 기록하는 `MEMORY.md` (자동 생성) |

처음엔 `CLAUDE.md` + `settings.json` 두 개만 있어도 활용의 80%는 커버된다.

## 슬래시 커맨드 (터미널/Code 탭 전용)

| 명령 | 기능 |
|---|---|
| `/model` | 사용할 모델 변경 (예: `/model opus`) |
| `/effort` | 추론 강도 고정 (예: `/effort xhigh`) |
| `/plan` | 실행 전 계획부터 세우는 계획 모드 |
| `ultrathink` | 프롬프트에 넣으면 해당 답변 한 번을 극한까지 깊게 추론 |
| `/compact` | 길어진 대화를 요약해 컨텍스트를 가볍게 |
| `/clear` | 대화 초기화 |
| `/rewind` | 이전 체크포인트로 복구 |
| `/resume` | 지난 세션 이어가기 |
| `/memory` | `CLAUDE.md`(장기기억) 편집 |
| `#` + 메시지 | 그 내용을 메모리에 즉시 저장 |
| `@파일명` / `@폴더/` / `@URL` | 파일·폴더·웹페이지를 멘션해 바로 읽힘 |
| `/init` | 프로젝트 구조를 분석해 `CLAUDE.md` 자동 생성 |
| `/code-review`, `/simplify`, `/security-review` | 코드 리뷰 / 단순화 / 보안 취약점 점검 |
| `/permissions` | 권한 관리 |
| `/mcp` | 연결된 [[MCP]] 서버 확인·관리 |
| `/agents` | 서브에이전트 관리 |
| `/fork` | 현재 대화에서 가지를 쳐 새 세션으로 분기 (A/B 실험용) |
| `/background` | 오래 걸리는 작업을 백그라운드로 전환 |
| `/checkup`, `/doctor` | 설정 자동 점검·청소 / 설치 상태 진단 |
| `/cost`, `/usage` | 세션 토큰 비용 / 플랜 사용량 확인 |
| `/export` | 대화를 파일로 내보내기 |
| `/plugins` | 플러그인 마켓플레이스 |
| ESC 두 번 | 진행 중인 작업 즉시 중단 |
| 커스텀 커맨드 | `.claude/skills/이름/SKILL.md`를 만들면 나만의 `/이름` 명령이 생김 |

## 예약 작업과 자동화

- **Routines(예약 작업)**: 앱 사이드바에서 작업 내용과 주기를 등록. **클라우드**는 컴퓨터를 꺼도 실행되지만 최소 1시간 간격, **로컬**은 앱이 켜져 있어야 하지만 최소 1분 간격
- **`/loop 15m ...`**: 최대 3일간 반복 감시 (터미널)
- **`/schedule`**: 터미널에서 클라우드 예약 생성

## 플러그인과 CLAUDE.md 작성

- 플러그인은 스킬·자동화·앱 연결을 묶은 패키지. `+` 버튼 → Plugins 또는 `/plugin`으로 마켓플레이스 접근. 필요한 것 하나만 설치하는 것을 권장
- `/init`으로 `CLAUDE.md` 초안을 자동 생성한 뒤, 정체성·타깃·말투·금지 표현 등을 채운다. 200줄 이내로 짧고 구체적으로 쓸수록 잘 지켜진다

## 인수인계 (팀 공유)

`CLAUDE.md`, 스킬, 설정, 앱 연결 목록이 모두 작업 폴더 안 `.claude` 폴더에 저장되므로, 폴더를 통째로 압축·공유하면 다른 사람도 동일한 판단·결과물을 얻는다. 단, 앱 로그인 정보(토큰·비밀번호)는 폴더에 담기지 않으므로 각자 `/mcp`로 다시 로그인해야 한다.

## 실전 워크플로우: AI 회사(부서화) 패턴

Claude Code에 여러 "부서"를 만들어 업무를 역할별로 쪼개는 활용법. 한 명(AI)에게 조사·기획·검수·글쓰기를 전부 맡기면 결과가 애매해지지만, 부서별로 "오늘 할 일 / 지켜야 할 기준(3개) / 결과물 형태 / 다음 부서"를 문서 한 장에 정의해두면 품질이 눈에 띄게 올라간다.

- 콘텐츠 제작 기준 12부서 예시: 시장조사팀·브랜드분석팀·기획1팀·브랜드검수팀(QA)·기획2팀·영상제작팀·이미지제작팀·협업소통팀·정산팀·성과리뷰팀·자동화운영팀·비서실. 처음엔 시장조사·기획·검수·대본·비서실 5개만으로 시작해도 충분하다
- 부서 문서를 `AI_COMPANY.md` 같은 파일 하나에 정리해두고, Claude Code에게 "이 회사의 직원들이야"라고 역할을 부여한 뒤 "시장조사팀 → 기획1팀 → 검수팀 순서로 진행하고 TOP 3만 보고해줘. 내가 고르면 그때 다음 단계로"처럼 **의사결정 지점을 사람에게 남기는 것**이 핵심
- 안전 규칙을 문서 맨 위에 명시: 메일 실제 발송 금지(초안까지만), SNS 실제 게시 금지, 결제·구독 금지, 원본 파일 삭제·덮어쓰기 금지, 완료되지 않은 작업을 "완료"라고 보고 금지, 출처 없는 정보를 사실처럼 쓰기 금지
