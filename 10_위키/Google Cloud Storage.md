# Google Cloud Storage (GCS)

> Google Cloud에서 제공하는 확장성·내구성·가용성이 높은 객체 스토리지 서비스.

## 개요

Google Cloud Storage(GCS)는 파일을 폴더 구조가 아니라 "객체(Object)" 단위로 저장하는 객체 스토리지 서비스다. 일반 파일 서버처럼 용량을 미리 정해두고 쓰는 것이 아니라, 저장한 만큼만 비용을 내며 필요에 따라 페타바이트 단위까지 자동으로 늘어난다. [[Vertex AI]]의 학습 데이터 저장소, [[Cloud Run]]에 배포된 애플리케이션의 파일 저장소 등으로 다른 Google Cloud 서비스들과 함께 자주 쓰인다.

## 주요 특징

[[동국대_교육자료1]] p.6 인포그래픽 "Google Cloud — Google Cloud Storage란? — Google Cloud Storage(GCS)는 Google Cloud에서 제공하는 확장성, 내구성, 가용성이 높은 객체 스토리지 서비스입니다"의 "1. 주요 특징" 4가지를 원문 그대로 옮긴다.

- **높은 내구성과 가용성**: "데이터는 여러 위치에 중복 저장되어 99.999999999%(11 9's)의 내구성을 제공합니다."
- **무제한 확장성**: "데이터 양에 제한 없이 페타바이트(PB) 단위까지 저장할 수 있습니다."
- **보안 및 접근 제어**: "IAM, 암호화, 버킷 정책 등을 통해 안전하게 데이터를 보호하고 세밀한 접근 제어가 가능합니다."
- **비용 효율성**: "사용한 만큼만 지불하며, 다양한 스토리지 클래스 선택으로 비용을 최적화할 수 있습니다."

## 구성 요소

같은 슬라이드 "2. 구성 요소" 섹션의 정의와 예시다.

- **버킷(Bucket)**: "데이터를 담는 최상위 컨테이너" — 전역적으로 고유한 이름, 리전 또는 멀티 리전 위치 선택
- **객체(Object)**: "버킷에 저장되는 개별 데이터" — 파일과 메타데이터로 구성, 고유한 이름(키)으로 식별

슬라이드에 실린 실제 예시는 버킷 `my-bucket`(버킷 이름) 아래 다음 객체들이 있는 구조다:

```
my-bucket/
├── images/photo.jpg
├── videos/intro.mp4
├── docs/report.pdf
├── backup/database.sql
└── ...
```

그리고 "객체 구성" 표(원문):

| 구성 요소 | 설명 |
|---|---|
| 데이터 | 실제 파일 내용 |
| 메타데이터 | 크기, 유형, 생성 시간 등 |
| 객체 이름(키) | 버킷 내에서 객체를 식별하는 고유 경로 |

아래는 위 구조를 CLI로 재현해보기 위해 편집 과정에서 작성한 예시로, 원본 자료에 실제로 실린 명령어는 아니다.

```bash
# 버킷 생성 — 편집자 작성
gcloud storage buckets create gs://my-app-bucket --location=asia-northeast3

# 파일(객체) 업로드
gcloud storage cp ./report.pdf gs://my-app-bucket/reports/report.pdf

# 버킷 내 객체 목록 확인
gcloud storage ls gs://my-app-bucket/reports/
```

## 스토리지 클래스

같은 슬라이드 "3. 스토리지 클래스" 섹션 4가지를 원문 그대로 옮긴다(괄호 안은 슬라이드에 함께 표기된 특성).

| 클래스 | 용도(원문) |
|---|---|
| Standard | 자주 액세스하는 데이터에 적합 (높은 가용성, 짧은 지연 시간) |
| Nearline | 월 1회 정도 액세스하는 데이터에 적합 (저비용, 약간 긴 검색 시간) |
| Coldline | 분기별 1회 정도 액세스하는 데이터에 적합 (더 낮은 비용, 긴 검색 시간) |
| Archive | 연 1회 미만 액세스하는 데이터에 적합 (가장 낮은 비용, 긴 검색 시간) |

> 참고(일반 배경지식, 이 표 자체는 슬라이드 원문이지만 정확한 단가는 여기 없음): 실제 GB당 단가·최소 보관 기간 등은 시점·리전마다 다르므로 공식 요금표 확인이 필요하다.

## 활용 사례

같은 슬라이드 "4. 활용 사례" 5가지(원문): 백업 및 재해 복구("중요 데이터를 안전하게 백업하고 재해 발생 시 빠르게 복구"), 미디어 저장 및 스트리밍("대용량 이미지, 동영상 파일을 저장하고 전 세계 사용자에게 제공"), 데이터 레이크 및 분석("빅데이터를 저장하고 분석/ML 워크로드에 활용"), 정적 웹사이트 호스팅("정적 웹사이트 파일을 저장하고 전 세계에 빠르게 배포"), 장기 보관("규정 준수, 기록 보관, 아카이브 데이터를 장기 보관").

"5. 주요 연동 서비스"로 명시된 목록: Compute Engine, BigQuery, Cloud Functions, Dataflow, Cloud Dataproc. 예를 들어 GCS에 파일이 업로드되면 Cloud Functions가 자동으로 트리거되어 후처리를 수행하는 식의 이벤트 기반 파이프라인을 구성할 수 있다(이 예시 자체는 일반적으로 알려진 활용 패턴을 편집 과정에서 보충한 것).

## 비교: GCS vs 로컬/전통적 파일 서버 (참고)

> 출처 자료에 없는 일반적 비교로, 이해를 돕기 위해 편집 과정에서 추가했다.

로컬 디스크나 자체 파일 서버는 초기 구성이 단순하고 네트워크 지연이 없다는 장점이 있지만, 용량이 차면 직접 증설해야 하고 다중 지역 복제·고가용성을 스스로 구현해야 한다. GCS는 그런 복제·확장·장애 대응을 서비스 차원에서 대신 처리해주는 대신, 네트워크를 통한 접근이라는 특성상 아주 낮은 지연시간이 필요한 로컬 I/O 작업에는 적합하지 않다.
