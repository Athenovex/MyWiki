# RAG (검색 증강 생성)

> 사용자의 질문에 대해 관련 정보를 외부 지식베이스에서 검색하고, 그 정보를 바탕으로 LLM이 더 정확하고 신뢰할 수 있는 답변을 생성하는 방식.

## 개요

대규모 언어모델(LLM)은 학습 시점까지의 지식만 파라미터 안에 압축해 담고 있어, 학습 이후에 생긴 정보나 학습되지 않은 사내 문서 같은 비공개 지식에는 답하지 못하거나 그럴듯하게 지어낸 답변(환각, Hallucination)을 내놓기 쉽다. RAG는 이 문제를 LLM 자체를 다시 학습시키는 대신, 응답 생성 직전에 신뢰할 수 있는 외부 지식베이스(위키피디아, 기업 문서, 매뉴얼 등)에서 관련 정보를 검색해 프롬프트에 끼워 넣는 방식으로 해결한다. 즉 LLM의 고정된 "내부 지식"을 매 질문마다 갱신 가능한 "외부 지식"으로 보완하는 구조다.

## 작동 흐름 (5단계)

1. **질문 입력(Query)**: 사용자가 자연어로 질문(프롬프트)을 입력하는 시작 단계. 이 질문은 다음 단계에서 지식베이스를 검색할 때 검색어(Query)로도 그대로 쓰인다.
2. **관련 정보 검색(Retrieval)**: 입력된 질문을 [[임베딩]]으로 변환한 뒤, 벡터 데이터베이스([[FAISS]] 등)에 저장된 문서 조각들과 유사도를 비교해 가장 관련성 높은 정보를 찾아낸다.
3. **관련 정보 전달**: 검색된 문서 조각을 가공 없이 다음 단계로 넘겨, LLM이 답변을 만들 때 참고할 맥락(Context)으로 준비한다.
4. **맥락이 포함된 입력 전달(Augmentation)**: 원래 사용자 질문과 검색된 정보를 하나의 프롬프트로 합쳐 LLM에 입력한다. "증강(Augmented)"이라는 이름은 이 단계에서 유래한다 — 질문 자체는 그대로 두고 답변에 필요한 맥락만 덧붙이는 것.
5. **답변 생성(Generation)**: LLM이 프롬프트에 포함된 질문과 검색된 맥락을 함께 이해하고, 그 맥락에 근거한 답변을 생성한다.

지식베이스는 웹 문서(예: 위키피디아), 문서 파일(PDF·DOCX), 데이터베이스 등 다양한 외부 지식원이 될 수 있다.

아래는 출처 자료의 "RAG 한눈에 이해하기" 다이어그램에 실린 예시를 그대로 옮긴 것이다.

```
[1. 질문 입력]
사용자: "위키피디아란 무엇인가요?" (사용자가 질문(프롬프트) 입력)

[2. 관련 정보 검색]
질문(Query)을 바탕으로 지식베이스(웹 문서·문서 파일·데이터베이스 등)에서 관련 정보 검색

[3. 관련 정보 전달]
검색된 정보를 LLM에 전달하여 맥락(Context) 강화

[4. 맥락이 포함된 입력 전달]
사용자 질문 + 관련 정보(검색 결과)를 합쳐 LLM에 입력

[5. 답변 생성]
LLM이 맥락을 이해하고, 더 정확하고 신뢰성 높은 답변 생성
→ "답변: 위키피디아는 누구나 편집할 수 있는 온라인 백과사전입니다..."
```

## 장점

- **최신 정보 반영**: 모델을 재학습하지 않고 지식베이스 문서만 갱신해도 최신 정보를 답변에 반영할 수 있다.
- **환각(Hallucination) 감소**: 실제로 검색된 문서에 근거해 답하므로 근거 없는 내용을 지어낼 가능성이 줄어든다.
- **출처 기반의 신뢰성 향상**: 어떤 문서에서 답을 가져왔는지 함께 제시할 수 있어 답변을 검증하기 쉽다.
- **도메인 특화 지식 활용 가능**: LLM이 학습하지 않은 사내 문서·전문 자료도 검색 대상에 포함시켜 답변에 활용할 수 있다.

## RAG와 파인튜닝(Fine-tuning) 비교

출처 자료에는 없는 내용이지만, RAG를 이해할 때 자주 함께 비교되는 대안이라 일반적으로 알려진 내용을 바탕으로 위키 편집 과정에서 정리해 추가한다.

| | RAG | 파인튜닝 |
|---|---|---|
| 지식 갱신 방법 | 지식베이스 문서만 교체·추가 | 모델 가중치를 다시 학습 |
| 최신성 | 문서만 바꾸면 즉시 반영 | 재학습 전까지 반영되지 않음 |
| 비용 | 상대적으로 저렴 (검색 인프라만 필요) | GPU 학습 비용·시간 소요 |
| 근거 제시 | 검색된 문서를 근거로 제시 가능 | 답변의 근거를 추적하기 어려움 |
| 적합한 용도 | 자주 바뀌는 정보, 사내 문서 Q&A | 말투·형식·특정 태스크 수행 방식을 모델 자체에 각인 |

두 방식은 서로 배타적이지 않고 함께 쓰이기도 한다 (예: 특정 말투로 답하도록 파인튜닝한 모델에 RAG로 최신 정보를 검색해 붙이는 방식).
