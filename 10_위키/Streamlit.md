# Streamlit

> Python만으로 데이터 앱(웹 애플리케이션)을 쉽고 빠르게 만들 수 있는 오픈소스 프레임워크.

## 개요

Streamlit은 프론트엔드(HTML/CSS/JS)를 따로 작성하지 않고 순수 Python 스크립트만으로 데이터 앱·대시보드를 만들 수 있는 오픈소스 프레임워크다. 스크립트를 위에서 아래로 실행하는 방식으로 동작하며, 코드에 위젯 함수를 호출하는 것만으로 버튼·슬라이더·표 같은 UI 요소가 만들어진다. 데이터 분석가·ML 엔지니어처럼 프론트엔드 경험이 적은 사람도 결과물을 빠르게 웹으로 공유할 수 있게 하는 것이 핵심 가치다.

## 주요 특징

[[동국대_교육자료1]] p.17 인포그래픽 "Streamlit 이란? — Streamlit은 Python만으로 데이터 앱(웹 애플리케이션)을 쉽고 빠르게 만들 수 있는 오픈소스 프레임워크입니다"의 "주요 특징" 5가지를 원문 그대로 옮긴다.

- **Python 기반**: "Python 스크립트만으로 웹 앱을 개발할 수 있습니다."
- **빠른 개발**: "코드를 변경하면 자동으로 앱이 새로고침되어 즉시 반영됩니다."
- **풍부한 구성 요소**: "데이터 표시, 차트, 테이블, 입력 폼 등 다양한 위젯을 제공합니다."
- **손쉬운 배포**: "몇 번의 명령으로 공유 가능한 웹 앱으로 배포할 수 있습니다."
- **오픈소스 & 커뮤니티**: "무료로 사용 가능하며 활발한 커뮤니티의 지원을 받을 수 있습니다."

## 작동 원리

같은 슬라이드 "작동 원리" 4단계(원문): Python 코드 작성(Streamlit 스크립트 `.py` 파일 작성) → 실시간 실행(코드가 실행되며 앱이 자동으로 렌더링) → 웹 브라우저 표시(사용자에게 인터랙티브한 웹 앱을 제공) → 상호작용 & 업데이트(사용자 입력에 따라 앱이 동적으로 업데이트).

> 참고(일반 배경지식, 출처에 없음): 내부적으로는 사용자가 위젯을 조작할 때마다 스크립트 전체를 위에서 아래로 다시 실행하는 방식이다. 일반적인 SPA(React 등)처럼 컴포넌트 단위로만 다시 그리는 구조와는 다르며, 이는 개발이 단순해지는 대신 상태 관리를 세밀하게 제어하기 어렵다는 제약으로도 이어진다.

### 슬라이드에 실린 실제 예제 코드

아래는 편집자가 지어낸 예시가 아니라, p.17 슬라이드 "간단한 예제 코드" 패널에 그대로 실려 있는 코드를 그대로 옮긴 것이다.

```python
import streamlit as st
import pandas as pd

st.title("📊 Streamlit 예제 앱")
st.write("Streamlit으로 데이터를 시각화해보세요!")
st.sidebar.header("설정")
option = st.sidebar.selectbox("차트 유형", ["막대 차트", "선 차트"])
data = pd.DataFrame({
    '항목': ['A', 'B', 'C', 'D'],
    '값': [10, 20, 15, 25]
})
if option == "막대 차트":
    st.bar_chart(data.set_index('항목'))
else:
    st.line_chart(data.set_index('항목'))
```

같은 슬라이드 우측 "실행 결과 예시" 패널은 이 코드가 만드는 화면을 브라우저 창 형태로 보여준다: 좌측 사이드바에 "설정" 제목과 "차트 유형" 드롭다운("막대 차트" 선택 상태), 우측 메인 영역에 제목 "📊 Streamlit 예제 앱"과 안내문 "Streamlit으로 데이터를 시각화해보세요!", 그 아래 A·B·C·D 네 항목에 대해 값이 약 10·20·15·25인 파란색 막대 그래프가 렌더링되어 있다. 상단 우측에는 "Deploy" 버튼이 보인다.

## 활용 분야

같은 슬라이드 "활용 분야" 5가지(원문): 데이터 분석 대시보드("데이터를 분석하고 시각화"), 머신러닝 모델 시연("모델 예측 결과를 인터랙티브하게 제공"), 내부 도구 & 자동화("사내 업무용 도구나 자동화 앱 구축"), 교육 & 학습("학습용 앱이나 강의 자료를 쉽게 공유"), 빠른 프로토타이핑("아이디어를 빠르게 앱으로 만들어 검증하고 공유"). 특히 모델을 다 만든 뒤 "일단 팀 안에서 써볼 수 있는 화면"이 급하게 필요할 때, 정식 프론트엔드 개발 없이도 짧은 시간 안에 데모를 띄울 수 있다는 점이 자주 언급되는 장점이다.

## 배포

같은 슬라이드 "배포 방법" 패널이 보여주는 3단계(원문): `streamlit run app.py`로 "로컬에서 실행" → **Streamlit Community Cloud**로 "또는 클라우드에 배포" → "공유 가능한 URL로 누구나 접속 가능". "대표 명령어" 패널에 실린 명령어 원문:

```bash
streamlit run app.py    # 앱 실행
streamlit share app.py  # 앱 공유
pip install streamlit   # 설치
```

슬라이드 한 줄 요약(원문): "Streamlit은 Python만으로 데이터 앱을 쉽고 빠르게 만들고, 공유할 수 있게 도와주는 강력한 도구입니다."

더 많은 트래픽·커스텀 도메인·사내 보안 요구가 있으면 [[Cloud Run]] 같은 컨테이너 플랫폼에 직접 배포하기도 한다(이 연결 자체는 이 자료 두 곳 모두에서 다뤄지는 강의 커리큘럼 흐름— 13:30~15:30 "Streamlit 활용 웹 UI 구현" 다음 15:30~17:00 "Cloud Run 초고속 배포" — 이지만, Dockerfile 코드 자체는 원본 슬라이드에 실려 있지 않다). 아래는 그 배포를 위한 최소 구성 예시로, 편집 과정에서 작성했다(원본 자료에 실제로 실린 코드는 아님).

```dockerfile
# Dockerfile — 편집자 작성 예시
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["streamlit", "run", "app.py", "--server.port=8080", "--server.address=0.0.0.0"]
```

## 비교: Streamlit vs 풀스택 프론트엔드 프레임워크 (참고)

> 출처 자료에 없는 일반적 비교로, 이해를 돕기 위해 편집 과정에서 추가했다.

| 항목 | Streamlit | React/Vue + 별도 백엔드 API |
|---|---|---|
| 개발 속도 | 매우 빠름 (Python만으로) | 느림 (프론트/백엔드 별도 구현) |
| UI 커스터마이징 자유도 | 제한적 (제공 위젯 범위 내) | 완전히 자유로움 |
| 적합한 규모 | 프로토타입, 내부 도구, 데모 | 다수 사용자를 위한 정식 프로덕트 |
| 상태관리·라우팅 | 프레임워크가 단순화(전체 재실행 방식) | 개발자가 직접 설계 |

빠르게 검증하거나 소수 내부 사용자를 대상으로 한다면 Streamlit이 유리하고, 복잡한 사용자 흐름·세밀한 UI·대규모 트래픽이 필요한 정식 서비스라면 별도 프론트엔드 프레임워크가 더 적합하다.
