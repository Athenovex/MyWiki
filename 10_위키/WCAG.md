# WCAG (Web Content Accessibility Guidelines)

> W3C의 웹 접근성 이니셔티브(WAI)가 만든 국제 표준. 시각·청각·운동·인지 장애가 있는 사용자도 웹 콘텐츠를 인식·조작·이해할 수 있도록 만들기 위한 성공 기준(Success Criteria)의 집합이다.

## 개요

WCAG는 하나의 확정된 체크리스트가 아니라 버전이 쌓이며 확장되는 표준이다. WCAG 2.0(2008)을 기반으로 2.1(2018)이 모바일·저시력·인지 장애 관련 기준을 추가했고, 2.2(2023)가 다시 몇 개를 더했다 — 이후 버전은 이전 버전을 포함(상위 호환)하는 구조라, "WCAG 2.1을 준수한다"는 것은 2.0 기준을 전부 포함해서 지킨다는 뜻이다. 각 성공 기준은 검증 가능한 조건문 형태로 쓰여 있어(모호한 권고가 아니라 "지켰다/안 지켰다"를 판정할 수 있는 문장), 감사(audit)나 법적 준수 확인에 쓸 수 있다는 것이 다른 디자인 가이드라인과의 차이점이다.

## 준수 수준 (Conformance Level): A / AA / AAA

성공 기준마다 A·AA·AAA 세 등급 중 하나가 매겨져 있고, 등급이 올라갈수록 지키기 까다롭거나 모든 콘텐츠 유형에 일괄 적용하기 어려운 기준이 포함된다.

| 등급 | 의미 | 실무 적용 |
|---|---|---|
| A | 최소 수준. 이걸 못 지키면 일부 사용자에게 콘텐츠 자체가 아예 막힘 | 반드시 지켜야 하는 하한선 |
| AA | 실무 표준. 대부분의 접근성 법규·조달 요건(미국 ADA/섹션508, EU EN 301 549, 한국 K-WAH 등)이 요구하는 수준 | **일반적으로 목표로 삼는 등급** |
| AAA | 최고 수준. 수어 통역 제공처럼 모든 콘텐츠·서비스에 일괄 적용하기 어려운 기준 포함 | W3C 스스로도 "웹사이트 전체에 AAA를 강제하지 말 것"을 권고 — 콘텐츠 특성에 맞게 선택 적용 |

## 4대 원칙 (POUR)과 13개 가이드라인

WCAG의 모든 성공 기준은 4개의 상위 원칙 아래 13개 가이드라인으로 묶여 있다. 원칙 자체는 "지켜야 할 규칙"이 아니라 "왜 이 규칙들이 필요한가"를 설명하는 상위 개념이다.

### 1. 인식의 용이성 (Perceivable)

정보와 UI 요소는 사용자가 인식할 수 있는 방식으로 제시되어야 한다 — 즉 콘텐츠가 어떤 감각(시각/청각)으로도 최소 한 가지 경로로는 전달되어야 한다는 원칙이다.

- **1.1 텍스트 대체 (Text Alternatives)**: 이미지·아이콘·차트처럼 텍스트가 아닌 콘텐츠에 대체 텍스트를 제공해, 스크린리더가 읽거나 점자로 바꾸거나 필요시 더 쉬운 말로 바꿀 수 있게 한다.
- **1.2 시간 기반 미디어 (Time-based Media)**: 영상·음성 콘텐츠에 자막, 오디오 설명, 대본을 제공해 청각·시각 장애가 있는 사용자도 같은 정보를 얻게 한다.
- **1.3 적응 가능성 (Adaptable)**: 시각적 레이아웃에 의존하지 않고도(예: 스타일을 껐을 때, 스크린리더로 읽을 때) 콘텐츠의 구조와 관계(제목, 목록, 표, 입력 순서 등)가 프로그램적으로 파악되도록 마크업한다.
- **1.4 구별 가능성 (Distinguishable)**: 색상 대비, 텍스트 크기 조절, 배경음 분리 등으로 콘텐츠를 배경과 쉽게 구별하고 시각·청각적으로 커스터마이징할 수 있게 한다. (예: 저시력 사용자를 위한 명도 대비 기준이 여기 속한다)

### 2. 운용의 용이성 (Operable)

UI 컴포넌트와 내비게이션은 조작 가능해야 한다 — 마우스가 아니라 키보드만으로, 혹은 충분한 시간 안에 조작할 수 있어야 한다는 원칙이다.

- **2.1 키보드 접근성 (Keyboard Accessible)**: 모든 기능을 키보드만으로 조작할 수 있어야 하며, 포커스가 특정 요소에 걸려 빠져나오지 못하는 "키보드 트랩"이 없어야 한다.
- **2.2 충분한 시간 (Enough Time)**: 세션 만료, 자동 넘어가는 슬라이드처럼 시간 제한이 있는 콘텐츠는 사용자가 시간을 늘리거나 정지할 수 있어야 한다.
- **2.3 발작과 신체 반응 (Seizures and Physical Reactions)**: 초당 3회 이상 번쩍이는 콘텐츠처럼 광과민성 발작을 유발할 수 있는 요소를 제한한다.
- **2.4 탐색 가능성 (Navigable)**: 반복 블록 건너뛰기 링크, 명확한 페이지 제목, 논리적인 포커스 순서, 의미가 드러나는 링크 텍스트 등으로 사용자가 지금 어디에 있고 어디로 갈 수 있는지 파악하게 돕는다.
- **2.5 입력 방식 (Input Modalities)**: 터치·펜·음성 등 마우스 이외의 입력 방식도 지원하고, 복잡한 제스처(핀치 줌 등)에는 단순한 대안을 함께 제공한다.

### 3. 이해의 용이성 (Understandable)

정보와 UI 작동 방식은 이해할 수 있어야 한다 — 텍스트를 읽을 수 있고, 화면이 예측 가능하게 동작하며, 실수를 했을 때 도움을 받을 수 있어야 한다는 원칙이다.

- **3.1 가독성 (Readable)**: 페이지의 언어를 명시하고(스크린리더 발음을 위해), 일반적이지 않은 단어·약어에는 설명을 제공한다.
- **3.2 예측 가능성 (Predictable)**: 포커스가 옮겨가거나 입력값이 바뀔 때 페이지 맥락이 사용자 모르게 갑자기 바뀌지 않아야 하고, 같은 기능의 UI는 사이트 전체에서 일관되게 배치·동작해야 한다.
- **3.3 입력 지원 (Input Assistance)**: 폼 입력 오류를 텍스트로 명확히 알려주고, 어떻게 고쳐야 하는지 제안하며, 결제·법적 서약처럼 중요한 제출에는 확인·취소 기회를 준다.

### 4. 견고성 (Robust)

콘텐츠는 스크린리더를 포함한 다양한 보조 기술과 미래의 다양한 브라우저·기기에서도 안정적으로 해석될 수 있어야 한다는 원칙이다.

- **4.1 호환성 (Compatible)**: HTML을 명세대로 정확히 작성하고(태그 중첩·닫힘 오류 없이), 커스텀 UI 컴포넌트에는 ARIA로 이름(name)·역할(role)·상태(state)가 프로그램적으로 노출되도록 해 보조 기술이 올바르게 해석하게 한다.

## 실무에서 참고하는 법

원본 문서(Quickref)는 웹사이트에서 **기술 스택(HTML/CSS/PDF 등)·준수 수준(A/AA/AAA)·성공 기준 버전(2.0/2.1/2.2)**을 필터링해 자신의 프로젝트에 해당하는 항목만 좁혀볼 수 있는 대화형 참고서다. 각 성공 기준마다 (1) 충분한 기법(Sufficient Techniques) — 그 기준을 만족시키는 구체적 구현 방법 여러 개, (2) 실패 사례(Failures) — 흔히 저지르는 잘못된 구현 패턴이 함께 정리되어 있어, "이 기준을 지켰다고 판단하는 근거"와 "이렇게 하면 어긴 것"을 동시에 확인할 수 있는 구조다. 실제 기준 문구·기법 목록은 버전에 따라 계속 갱신되므로, 감사나 구현 시에는 아래 원본(영문)이나 W3C 공식 사이트를 직접 확인하는 것이 정확하다.
