# 랜딩페이지

> 광고를 클릭한 방문자가 "착지"하는, 전환(구매·신청)이라는 단 하나의 목적을 위한 단독 페이지. 일반 홈페이지가 "백화점"이라면 랜딩페이지는 "이 제품만 파는 단독 매대"다.

> 아래 헤드라인 예시, CTA 버튼 문구, 신뢰 장치 목록은 [[AI마케팅_이커머스_전문가과정]] 원본 슬라이드(p.73-80)에 실제로 등장하는 문구를 그대로 인용했다. 다만 헤드라인 예시들은 원본에서도 특정 제품 하나에 결부되지 않은 일반 예시로 제시된다("설거지가 3분으로 줄어듭니다"처럼 무드컵 텀블러와 무관한 예시가 섞여 있다). 무드컵을 직접 지목한 실제 자료는 "AI로 상세페이지·랜딩페이지 카피 완성하기" 슬라이드(p.77)의 프롬프트 예시이며, 원본은 이 프롬프트가 실제로 만들어낼 6단 구조 완성 카피 자체는 싣지 않는다. 아래 "6단 구조를 무드컵에 대입한 예시"는 그 프롬프트를 실행하면 나올 법한 결과물을 보여주기 위해 편집자가 작성한 것으로 명시했다.

## 전환되는 랜딩페이지의 6단 구조

랜딩페이지는 방문자가 스크롤을 내리며 "이게 나에게 필요한가?" → "믿을 만한가?" → "지금 살까?" 순서로 판단을 좁혀가도록 설계된 6단 흐름이다. 중간 단계를 건너뛰면 방문자가 확신을 얻지 못한 채 이탈한다. (원본 슬라이드 p.73, 구조 명칭·설명 그대로)

1. **헤드라인(첫 화면)**: 3초 안에 "이게 나에게 필요하다"를 느끼게 하는 한 문장.
2. **문제 공감**: 고객이 겪는 불편을 짚어 "내 얘기다" 싶게 만든다.
3. **해결·핵심 혜택**: 제품이 그 문제를 어떻게 푸는지, 기능이 아니라 혜택 중심으로 설명한다.
4. **증거(후기·수치)**: 후기·판매량·인증으로 신뢰를 쌓는다.
5. **제안·가격**: 혜택·구성·가격을 명확히 제시해 "무엇을 얼마에 받는지" 헷갈리지 않게 한다.
6. **행동유도(CTA)**: "지금 구매하기" 버튼처럼 다음 행동을 명확한 동사로 지시한다.

원본이 실제로 제시하는 무드컵 프롬프트(p.77, 그대로 인용):

```
너는 전환율 높은 상세페이지 전문 카피라이터야. '무드컵' 텀블러의 랜딩페이지를
헤드라인→문제공감→혜택3→후기→가격제안→CTA 순서로 써줘.
각 섹션은 짧고 스캔하기 쉽게.
```

이 프롬프트를 실행하면 나올 법한 결과를 6단 구조에 대입해본 예시(편집자 작성, 원본에 실린 완성 카피 아님):

```
① 헤드라인   : "손에 감기는 그립감, 무드컵"
② 문제 공감  : "텀블러 샀는데 손에 안 맞아 자꾸 흘리지 않으셨나요?"
③ 핵심 혜택  : "손에 딱 맞는 그립감과 파스텔 컬러로 매번 다시 손이 갑니다"
④ 증거      : "20~30대 여성 고객 다수가 선택한 감성 텀블러 (구체 수치는 원본 미제공)"
⑤ 제안·가격  : "무선 세척 간편, 오늘 주문 시 40% 할인"
⑥ CTA      : "40% 할인가로 담기"
```

## 헤드라인 작성법

혜택을 앞세우기, 구체적 숫자 사용, 타깃을 콕 집기, 궁금하게 만들기 — 이 네 가지 중 하나 이상을 담으면 막연한 헤드라인보다 클릭·체류가 늘어난다.

원본 슬라이드(p.74)가 각 원칙에 실제로 붙인 예시(그대로 인용 — 무드컵에 한정되지 않은 일반 예시들이다):

```
혜택을 앞세워라 : "설거지가 3분으로 줄어듭니다"
구체적 숫자    : "1만 명이 선택한 그 텀블러"
타깃을 콕 집어라 : "커피 못 끊는 직장인을 위한"
궁금하게 만들어라 : "왜 재구매율이 80%일까?"
```

## 신뢰 장치

고객 후기, 판매·재구매 수치, 보장·환불 정책, 인증·수상·미디어 노출, 비포/애프터, FAQ — 방문자는 광고 문구는 의심하지만 "다른 사람의 경험"과 "명시된 보장"은 상대적으로 신뢰한다. 페이지 안에 이런 제3자 근거가 하나도 없으면 4단계(증거)가 비어 전환이 떨어지기 쉽다. (원본 슬라이드 p.75, 6개 항목 그대로)

## CTA(행동유도 버튼) 작성법

동사로 명확하게("제출" 대신 "무료로 시작하기"), 혜택을 담기, 눈에 띄게, 여러 번 배치, 긴박감 부여("오늘까지") — CTA는 페이지 맨 아래 한 번만 두지 않고 스크롤 중간중간 반복 배치하는 것이 일반적이다.

원본 슬라이드(p.76)가 실제로 예시로 든 CTA 버튼 문구(그대로 인용):

```
"40% 할인가로 담기 ›"
"오늘 자정까지 · 무료배송"
"30일 무료 반품 보장"
```

## 모바일 퍼스트

고객의 8~9할은 모바일로 접속한다. 따라서 데스크톱 화면을 기준으로 설계한 뒤 모바일에 맞춰 축소하는 방식이 아니라, 처음부터 큰 글씨·짧은 문단, 엄지로 누르기 쉬운 큰 버튼, 가벼운 로딩(이미지 용량 최소화)을 우선하는 순서로 설계해야 한다. (원본 슬라이드 p.79)

## 테스트로 개선하기

가설 세우기 → 한 가지만 변경(A/B) → 데이터 확인(전환율·체류시간) → 반영·반복. 한 번에 여러 요소(헤드라인+CTA+이미지 등)를 동시에 바꾸면 전환율이 달라져도 어느 요소 덕분인지 알 수 없으므로, 한 번에 하나의 변수만 바꾸는 것이 원칙이다. (원본 슬라이드 p.82, 4단계 흐름 그대로)
