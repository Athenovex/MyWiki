# 임베딩 (Embedding)

> 단어나 범주를 컴퓨터가 이해할 수 있는 숫자 벡터로 변환하는 것. 원-핫 인코딩과 달리 단어 간 의미적 유사도를 반영하는 저차원 벡터 표현이다.

## 개요

원-핫 인코딩(One-Hot Encoding)은 단어의 존재 유무만 표현하고(차원 = 단어 집합 크기, 유사도 반영 안 됨), 임베딩은 의미적 유사도를 벡터 공간의 거리로 반영하는 저차원 벡터(예: 2~300차원)로 변환한다. 예: '사과'와 '바나나'는 임베딩 공간에서 가까운 벡터, '고양이'와 '강아지'도 가까운 벡터가 된다.

장점: 차원이 낮아 효율적, 단어 간 의미적 유사도/관계를 벡터 공간의 거리로 표현, 머신러닝/딥러닝 성능 향상에 기여.

아래는 출처 자료의 "임베딩(Embedding)이란?" 슬라이드에 실린 예시 단어 집합(사과·바나나·고양이·강아지)의 실제 벡터값이다.

```
원-핫 인코딩 (차원 = 단어 집합의 크기 4):
사과   = [1, 0, 0, 0]
바나나 = [0, 1, 0, 0]
고양이 = [0, 0, 1, 0]
강아지 = [0, 0, 0, 1]
→ 단어의 존재 유무만 표현. 차원이 매우 크고(단어 수가 많아지면 벡터도 길어짐),
  단어 간 유사도/관계가 전혀 반영되지 않는다.
  예) '사과'↔'바나나' 거리 = √2 (원-핫 벡터상에서 완전히 다른 벡터)

임베딩 (예시 차원 = 2차원, 실제로는 2·3·100·300차원 등 다양):
        차원1    차원2
사과     0.71    0.21
바나나   0.69    0.18
고양이  -0.40    0.66
강아지  -0.35    0.61
→ 단어의 의미와 유사도(관계)를 벡터 공간의 거리로 표현.
  '사과'와 '바나나'는 가까운 벡터(유사한 의미), '고양이'와 '강아지'도 가까운 벡터(유사한 의미)이며,
  두 그룹 사이는 서로 멀다(다른 의미).
```

## 유사도 계산 방법 (3가지)

출처 자료의 "임베딩 벡터의 유사도 구하는 방법 (3가지)" 슬라이드에 실린 정리 표다.

| 방법 | 무엇을 측정? | 값의 범위 | 유사할수록 | 특징 | 트랜스포머에서의 사용 |
|---|---|---|---|---|---|
| 유클리드 거리 | 두 점 사이의 직선 거리 | [0, ∞) | 0에 가까울수록 | 직관적, 해석 쉬움, 스케일에 영향 받음 | 직접 사용은 드묾 (주로 시각화, 클러스터링) |
| 코사인 유사도 | 두 벡터의 각도 | [-1, 1] | 1에 가까울수록 | 방향성 비교, 크기(길이)의 영향 적음 | 일반 임베딩 검색, 문서/단어 유사도, 추천 시스템 |
| 내적(점곱) 유사도 | 두 벡터의 방향 + 크기 | (-∞, ∞) | 클수록 | 크기와 방향을 모두 반영 | 트랜스포머의 핵심! (Self-Attention, Q·Kᵀ) |

언제 어떤 것을 쓸까 (출처 자료 원문):
- **코사인 유사도**: 대부분의 임베딩 검색, 의미적 유사도 비교에 가장 많이 사용
- **내적(점곱) 유사도**: 벡터의 크기 정보도 함께 반영하고 싶을 때, 트랜스포머 내부 연산
- **유클리드 거리**: 공간적 거리 기반 분석, 시각화, 군집화 등에 활용

아래는 출처 자료에 실린 예시(2차원 임베딩)를 그대로 옮긴, 세 방법을 동시에 계산해 비교한 예시다: A(사과)=[0.1, 0.2], B(바나나)=[0.2, 0.7], C(자동차)=[0.9, 0.1].

```
[유클리드 거리]
d(A,B) = √((0.1-0.2)² + (0.2-0.7)²) = √0.26 ≈ 0.51
d(A,C) = √((0.1-0.9)² + (0.2-0.1)²) = √0.65 ≈ 0.81
→ 결과: A와 B가 더 가까움(0.51 < 0.81) → '사과'와 '바나나'가 '자동차'보다 더 유사

[코사인 유사도]
sim(A,A) = 1 (자기 자신)
sim(A,B) = (0.1×0.2 + 0.2×0.7) / (√(0.1²+0.2²) × √(0.2²+0.7²)) ≈ 0.98
sim(A,C) = (0.1×0.9 + 0.2×0.1) / (√(0.1²+0.2²) × √(0.9²+0.1²)) ≈ 0.24
→ 결과: A와 B의 방향이 더 비슷함(0.98 > 0.24) → '사과'와 '바나나'가 '자동차'보다 더 유사

[내적(점곱) 유사도]
score(A,A) = 0.1×0.1 + 0.2×0.2 = 0.05 (자기 자신)
score(A,B) = 0.1×0.2 + 0.2×0.7 = 0.16
score(A,C) = 0.1×0.9 + 0.2×0.1 = 0.11
→ 결과: A와 B의 내적 값이 더 큼(0.16 > 0.11) → '사과'와 '바나나'가 '자동차'보다 더 유사
```

세 방법 모두 이 예시에서는 같은 결론(사과-바나나가 사과-자동차보다 유사)에 도달하지만, 측정 방식(거리/각도/방향+크기)이 다르므로 데이터 특성에 따라 결과가 달라질 수 있다.

## 활용

출처 자료에 구체적인 모델명은 나와 있지 않지만, 실무에서 자주 쓰이는 임베딩 모델을 이해를 돕기 위해 일반적으로 알려진 사실을 바탕으로 위키 편집 과정에서 덧붙인다: OpenAI의 `text-embedding-3-small`/`-large`, Google의 `text-embedding-004`, 오픈소스 `sentence-transformers` 계열 등. 어떤 모델을 쓰든 결과는 "고정된 차원의 실수 벡터"이며, 벡터 간 거리로 유사도를 비교하는 원리는 동일하다. [[RAG]]와 [[LangChain]] 파이프라인에서는 이렇게 만들어진 벡터가 [[FAISS]] 같은 벡터 DB에 저장되어 검색에 쓰인다.

## 관련 지식

- [[FAISS]] — 임베딩 벡터를 저장하고 유사도 검색을 수행하는 벡터 데이터베이스
- [[RAG]] — 질문과 문서를 임베딩해 유사도 기반으로 검색하는 데 사용
- [[LangChain]] — 문서를 임베딩으로 변환해 벡터 DB에 저장하는 파이프라인 제공
