### 📣 Fable 5 무료 기간, 7/12까지 연장됐습니다

가장 똑똑한 클로드 모델인 **Fable 5**의 무료 기간이 **7/7 → 7/12로 연장**됐어요.

- **7월 12일까지** — 주간 한도의 50% 선까지는 **지금 쓰는 요금제 안에서 무료**로 Fable 5를 쓸 수 있습니다.

- **7월 13일부터** — 무료가 끝나고, 쓴 만큼 **사용량 기반으로 과금**됩니다.

문제는, Fable 5가 **클로드 모델 중 가장 비싼 등급**이라는 거예요.
같은 일을 시켜도 모델에 따라 비용이 이만큼 차이 납니다.

| 모델 | 상대 비용 | 주로 쓰는 곳 |
| --- | --- | --- |
| Haiku | 1x | 빠른 답변, 단순·대량 작업 |
| Sonnet | 3x | 일상 업무의 대부분 (기본값) |
| Opus | 5x | 복잡하고 변수 많은 작업 |
| **Fable 5** | **10x** | 계획·판단, 무거운 일회성 작업 |

> ⏳ 
> 
> 즉, Fable로 하는 '생각하는 일'은 13일부터 제일** 비싼 작업**이 돼요.
> 그래서 무료인 지금, 답 몇 개 받고 끝내는 게 아니라 **"이것"부터 해둬야** 합니다.

---

### 🤔 왜 꼭 Fable로 세팅을 해둬야 할까?

'생각'이 필요한 일일수록, 모델이 똑똑해야 결과가 잘 나와요.
그리고 **현시점 가장 똑똑한 모델이 Fable 5**예요.

그런데 Fable이 좋은 결과를 내는 이유는 단순히 머리가 좋아서가 아니라,
**'일하는 방식'** 때문이라고 해요.

- **① 답을 내놓기 전에 스스로 점검합니다.
**바로 답부터 뱉지 않고 '컨텍스트 수집 → 작업 → 자가 검증'까지 한 번에 돌려요.
그래서 대충 답하고 끝내는 일이 적어요.

- **② 일일이 시키지 않아도 알아서 설계합니다.
**절차를 하나하나 떠먹여 주지 않아도 목표만 주면 스스로 방향을 잡습니다.

- **③ 큰 일을 쪼개서 나눠 처리합니다.
**덩어리 작업을 잘게 나눠 여러 에이전트에게 안정적으로 맡길 줄 압니다.

핵심은, 이 **'일하는 방식'은 파일(지침)로 옮겨 적을 수 있다**는 점이에요.

지금 Fable에게 이 방식을 **내 세팅으로 남겨두면**, 무료가 끝나고 더 저렴한 모델(Sonnet·Haiku)을 써도
그 세팅이 **Fable처럼 일하게** 만들어 줍니다.
실행이야 나중에 저렴한 모델이 해도 되지만,
**'생각'이 필요한 판단·설계는 지금 무료인 Fable에게** 시켜서 그 결과를 붙잡아 두는 거죠.

### 세팅 01. 나에게 딱 맞춘 개인 지침 만들기

가장 똑똑한 Fable에게 나를 관찰하고 빈틈만 인터뷰하게 해서,
**'나에 대한 설명서'를 한 번만 제대로 만들어두세요.
**이후엔 어떤 모델이든 Fable이 만들어준 설명서를 읽고 답변하게 됩니다.

**▶️ 실행 방법**

클로드 채팅에서 Fable 5를 선택하고 아래 프롬프트를 붙여넣으세요.
클로드가 물어보는 질문에 답하면, 나만의 개인 지침 파일이 완성됩니다.
완성된 지침을 ‘프로필 > 설정 > Claude 지침’ 칸에 붙여넣으면 됩니다.
(Claude Code를 쓴다면 아무 폴더에서나 실행해도 됩니다.)

```
당신은 나의 개인 지침 설계자다. 당신의 임무: 어떤 프로젝트에서든, 어떤 저렴한 모델이든 나를 이미 아는 것처럼 행동하게 만드는 사용자 레벨 CLAUDE.md를 만드는 것. 이 파일은 특정 프로젝트가 아니라 '나'에 관한 것이다.

다음 순서로 작업하라:

1. 묻기 전에 관찰하라(OBSERVE BEFORE ASKING). 접근할 수 있는 모든 것을 연구하라: 세션 히스토리, 프로젝트들, 기존 CLAUDE.md 파일, 메모리 파일, 저장된 프롬프트. 증거 기반의 프로필 초안을 만들어라: 내가 무엇을 작업하는지, 어떤 언어로 쓰고 어떤 언어의 답을 기대하는지, 내 질문이 얼마나 기술적인지, 무엇을 반복해서 교정하는지, 출력이 너무 길거나 짧거나 소극적이거나 과할 때 내가 어떻게 반응하는지.

2. 빈틈만 인터뷰하라(INTERVIEW ME ON THE GAPS ONLY). 증거로 추론할 수 없는 것만, 한 번에 3~5개씩, 가능하면 객관식으로 물어라. 최소한 다음을 다뤄라: 내 역할과 전문성 수준, 답변 스타일(언어, 길이, 어조, 코드 대 설명 비율), 스스로 행동할 때와 물어볼 때의 기준, 파괴적이거나 되돌릴 수 없는 작업에 대한 위험 감수 수준, 내 환경의 특이점, AI 출력에 대해 내가 가장 불만스러워하는 것. 새 답변이 초안을 더 이상 바꾸지 않으면 인터뷰를 멈춰라.

3. 파일 초안 작성(DRAFT THE FILE). 다음 층위로 사용자 레벨 CLAUDE.md를 써라:
   - 나는 누구인가(WHO I AM): 역할, 전문성, 답변의 눈높이를 맞추는 데 필요한 맥락.
   - 나에게 말하는 법(HOW TO TALK TO ME): 언어, 어조, 길이, 형식, 생략할 것.
   - 나를 위해 일하는 법(HOW TO WORK FOR ME): 행동할 때와 물어볼 때, 불확실성을 다루는 법, 나에게 "완료"란 무엇인지.
   - 하드 룰(HARD RULES): 절대/항상 목록. 짧고, 단호하고, 검증 가능하게.
   모든 규칙에 [observed](증거와 함께) 또는 [stated](내 답변에서) 태그를 붙여라. 취향을 절대 지어내지 마라; 확신이 없으면 대신 미해결 질문(OPEN QUESTIONS) 목록에 넣어라.

4. 스트레스 테스트(STRESS-TEST IT). 내가 할 법한 현실적인 요청 3개를 골라라. 각각에 대해, 이 파일만 따르는 저렴한 모델이 어떻게 답할지 두 줄로 보여라. 어떤 답이든 나를 거슬리게 할 것 같다면, 실패한 규칙을 고치고 수정 내용을 보여라.

5. 저장 및 보고(SAVE AND REPORT). 사용자 레벨 CLAUDE.md(~/.claude/CLAUDE.md)에 저장하되, 기존 내용과 병합하라 — 중복 없이, 모순 없이, 프로젝트 전용 규칙은 각 프로젝트에 남겨라. 그런 다음 최종 파일과, 당신이 가장 확신하지 못하는 규칙 3개를 보여라.
```

**✅ 얻을 수 있는 것:** 어떤 상황에서든 나에게 딱 맞춰서 답변하는 맞춤형 지침

### 세팅 02. Fable의 뇌로 생각하게 만들기

Fable이 좋은 결과를 내는 이유는 대부분 '일하는 방식' 때문입니다.
답하기 전에 계획하고, 가정을 점검하고, 내놓기 전에 스스로 검증해요.
**그 사고방식 자체를 규칙으로 옮겨** 프로젝트에 넣어두면,
그 방에서는 저렴한 모델도 Fable처럼 일합니다.

**▶️ 실행 방법**

클로드에서 새 **'프로젝트'**를 하나 만드세요(방 이름 예: `Fable 모드`).
그리고 아래 프로토콜을 프로젝트의 **지침 칸에 그대로 붙여넣으면** 끝입니다.
이후 품질이 중요한 대화는 전부 이 방에서 하면 됩니다.

```
너는 이 방에서 아래 프로토콜로 일한다. 어떤 요청이든 프로토콜을 생략할 수 없다.

## 답하기 전에
1. 요청의 진짜 목적을 한 줄로 다시 써라. 표면의 지시가 아니라, 사용자가 얻으려는 결과를.
2. 네가 가정하고 있는 것을 점검하라. 틀리면 결과물이 쓸모없어지는 가정이 하나라도 있으면 작업 전에 그것만 짧게 물어라. 그 외에는 묻지 말고 진행하라.
3. 결과물의 형태(형식, 길이, 톤)를 먼저 정하고 시작하라.

## 작업 중에
4. 처음 떠오른 답을 한 번 의심하라. "이게 틀렸다면 어디가 틀렸을까?"를 스스로 묻고, 확인한 뒤 진행하라.
5. 모르는 것을 아는 것처럼 쓰지 마라. 불확실한 부분은 불확실하다고 표시하고, 확인하는 방법을 함께 제시하라.
6. 요청받은 것만 하라. 요청 밖의 기능·수정·조언을 덧붙이지 마라. 덧붙일 가치가 있는 게 보이면 결과물 끝에 한 줄로만 제안하라.

## 내놓기 전에
7. 자기 검증 3가지를 통과해야 한다:
   - 목적 검증: 1번에서 쓴 목적을 실제로 달성했는가?
   - 요구 검증: 요청의 모든 항목을 빠짐없이 다뤘는가? 빠진 것이 있으면 지금 채워라.
   - 반대 검증: 깐깐한 상사가 이걸 본다면 어디를 지적할까? 그 지적을 미리 반영하라.
8. 결과물 먼저, 설명은 나중에. 과정 서술로 답을 시작하지 마라.

## 금지
- 확인 안 된 사실을 단정하는 것.
- "~일 수 있습니다"로 도망치며 판단을 회피하는 것. 판단이 필요하면 근거와 함께 한쪽을 골라라.
- 요구를 다 채우지 않고 끝났다고 말하는 것.
```

**✅ 얻을 수 있는 것:** 더 저렴한 모델이 Fable처럼 사고하게 하는 지침

### 세팅 03. 내 글쓰기·디자인 스타일 추출해두기

저렴한 모델도 규칙만 구체적이면 스타일 모방은 잘합니다.
문제는 그 규칙을 '뽑는' 일 — 그건 가장 똑똑한 Fable에게 시켜 두면 좋겠죠.
**내가 직접 만든 결과물을 주고 내 스타일을 역설계**시키세요.

**▶️ 실행 방법**

클로드 채팅에 내가 만든 결과물 3~5개(글, 인스타 캡션, 슬라이드, 디자인 캡쳐 등)를 **첨부**하고
아래 프롬프트를 붙여넣으세요. 결과로 나온 글쓰기·디자인 지침문은
새 프로젝트를 만든 후 ‘지침’ 칸에 넣어 두면 매번 그 스타일대로 결과물을 뽑아줍니다.

```
당신은 나의 스타일 분석가다. 다른 AI 모델이 "내가 만든 것 같은" 결과물을 재현할 수 있도록 내 스타일을 역설계하라.

1. 분석. 글이라면: 문장 길이, 어미와 말버릇, 자주 쓰는 표현과 피하는 표현, 어조, 글의 구성 습관, 이모지와 문장부호 사용. 디자인이라면: 색과 폰트의 경향, 레이아웃과 여백, 정보 밀도, 반복되는 시각 요소.

2. 규칙화. 분석 결과를 "따라 할 수 있는" 구체적 규칙으로 바꿔라. "따뜻한 느낌" 같은 추상어 금지. "한 문장은 대체로 N자 이내", "제목은 명사형으로 끝낸다"처럼 검증 가능하게.

3. 반례 포함. 각 규칙마다 내 스타일인 예와 내 스타일이 아닌 예를 한 줄씩 붙여라.

4. 출력. 두 가지로 포장하라: (a) 클로드 '스타일' 기능에 저장할 글쓰기 스타일 지침문, (b) 디자인 작업을 시킬 때 붙여넣을 디자인 브리프 템플릿.

5. 검증. 같은 주제로 내 스타일을 적용한 샘플과 적용하지 않은 샘플을 하나씩 만들어 비교하라. 둘이 비슷하다면 규칙이 덜 구체적인 것이니 1번부터 다시 파고들어라.
```

**✅ 얻을 수 있는 것:** 나만의 스타일로 저장할 글쓰기 지침문 + 디자인 가이드 템플릿

### 세팅 04. 내 프로젝트와 [CLAUDE.md](http://CLAUDE.md) 업그레이드하기

자주 쓰는 프로젝트에 들어가서 Fable에게 **지침과 실제 작업 기록을 대조**시키고,
기존 지침을 업그레이드할 수 있습니다.

**▶️ 실행 방법**

업그레이드하고 싶은 **프로젝트(또는 Claude Code 작업 폴더) 안에서** 새 채팅을 시작하고,
아래 프롬프트를 실행하세요.
프로젝트가 여러 개면 자주 쓰는 방부터 하나씩 반복하면 됩니다.
나온 결과물을 복사해 프로젝트 지침 칸에 새로 붙여넣습니다.
클로드코드에서는 새 지침으로 업데이트해달라고 말해주면 돼요!

```
당신은 나의 지침 감사관이다. 지금 우리가 있는 이 프로젝트(클로드 프로젝트 방 또는 Claude Code 작업 폴더)의 지침을, 저렴한 모델이 따라도 좋은 결과가 나오는 수준으로 업그레이드하라.

1. 현황 파악. 이 프로젝트의 현재 지침을 전부 읽어라: 프로젝트 지침 칸, CLAUDE.md, 지식 파일, 그 밖의 규칙 문서. 그리고 실제 작업의 흔적(이 방의 대화 기록, 폴더의 파일과 결과물, 내가 반복한 요청과 교정)을 지침과 대조할 수 있을 만큼 살펴라.

2. 진단. 지침과 현실 사이의 틈을 전부 나열하라: 모호한 것, 낡은 것, 서로 모순되는 것, 빠진 것, 그리고 지침에는 없는데 내가 매번 말로 시키고 있는 것. 각 항목에 근거를 한 줄씩 붙여라.

3. 질문. 진단만으로 정할 수 없는 것은 추측하지 말고 나에게 물어라. 한 번에 3개씩, 가능하면 객관식으로.

4. 재작성. 지침을 완전하고 모호함 없게 다시 써라. 포함할 것: 이 프로젝트의 목적, 결과물 형식, 지켜야 할 규칙, 하지 말 것, 완료 판정 기준. 기존의 하드 룰과 내 말투는 보존하고, 내가 말한 적 없는 취향은 지어내지 마라.

5. 전/후 보고. 바뀐 부분마다 한 줄 근거를 붙인 전/후 비교와, 남은 미해결 질문을 보여라. 마지막으로 완성본을 붙여넣을 위치(프로젝트 지침 칸 또는 CLAUDE.md)에 맞는 형태로 출력하라. 다른 파일은 건드리지 마라.
```

**✅ 얻을 수 있는 것:** 해당 프로젝트에 바로 붙여넣을 수 있는 업그레이드된 지침 완성본

### 세팅 05. 나만의 프롬프트 모음집 만들기

매번 즉석에서 대충 치는 요청들, 프롬프트를 '잘 쓰는' 능력 자체를 Fable에게 맡기세요. 내가 반복하는 일들을 **나만의 템플릿**으로 정교하게 제작해두면, 앞으로는 저렴한 모델에게 복붙만 하면 됩니다.

**▶️ 실행 방법**

클로드 채팅에서 아래 프롬프트를 실행하세요. 클로드가 후보 작업 목록을 보여주면, **주 1회 이상 실제로 하는 일만** 골라 확정하세요. 완성된 모음집은 노션이나 메모장에 저장해 두고 꺼내 쓰면 됩니다.

```
당신은 나의 프롬프트 엔지니어다. 내가 반복해서 시키는 일들을 최고 품질의 프롬프트 템플릿으로 만들어, 앞으로 저렴한 모델에게 복붙만 하면 되게 하라.

1. 수집. 내가 AI에게 자주 시키는 일을 질문으로 파악하라. 대화 히스토리에 접근할 수 있다면 그것도 살펴라. 템플릿으로 만들 가치가 있는 작업 후보 10개를 목록으로 만들어 나에게 확인받아라.

2. 제작. 확정된 작업마다 프롬프트 템플릿을 하나씩 만들어라. 각 템플릿의 조건:
   - [빈칸]에 내용만 채우면 바로 실행된다.
   - 역할, 목적, 결과물 형식, 품질 조건, 하지 말 것이 들어 있다.
   - 판단이 필요한 부분은 저렴한 모델에게 맡기지 말고 템플릿 안에서 미리 결정해 둔다.

3. 사용법. 각 템플릿에 한 줄 사용법과, 어떤 상황에서 꺼내 쓰는지 트리거를 붙여라.

4. 정리. 전체를 목차가 있는 하나의 문서로 정리하라. 자주 쓸 순서대로 배치하라.

5. 시험. 가장 자주 쓸 템플릿 1개를 골라 지금 실제로 실행해 보여라. 결과가 아쉬우면 템플릿을 고치고, 무엇을 왜 고쳤는지 말하라.
```

**✅ 얻을 수 있는 것:** 내가 진짜로 자주 쓰는 작업들만 모아 둔 진짜배기 프롬프트 모음집 문서
